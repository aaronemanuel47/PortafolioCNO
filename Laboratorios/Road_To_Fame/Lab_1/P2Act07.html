1. Nombre del Laboratorio

File path traversal, simple case

Fuente oficial: portswigger.net/web-security/file-path-traversal/lab-simple

2. Nivel

Apprentice

3. Tipo de Explotación

Path Traversal / Directory Traversal (CWE-22). Explotación del lado del servidor mediante manipulación del parámetro que referencia un nombre de archivo, sin validación ni canonicalización adecuada de la ruta resultante.

4. Objetivo del Laboratorio

La aplicación vulnerable es una tienda en línea que permite visualizar imágenes de los productos a través del endpoint /image?filename=NOMBRE. El objetivo del laboratorio es abusar de este mecanismo para leer el contenido del archivo /etc/passwd del sistema operativo subyacente, demostrando que el servidor no restringe el acceso a archivos fuera del directorio de imágenes previsto.

5. Explicación Técnica de la Vulnerabilidad

5.1 Concepto y Mecanismo

El Path Traversal (o Directory Traversal) ocurre cuando una aplicación recibe un dato del usuario (por ejemplo, un nombre de archivo) y lo concatena directamente a una ruta del sistema de archivos sin validarlo. En Unix/Linux, cada ../ hace que el sistema operativo suba un nivel en la jerarquía de directorios; esta resolución ocurre a nivel de kernel y es ajena a la lógica de la aplicación.

Si el servidor construye una ruta como base_dir + "/" + filename, y filename es ../../../etc/passwd, la ruta resultante equivale a /etc/passwd, aunque el desarrollador nunca la escribió de forma literal. La aplicación la entrega igualmente porque nunca comparó la ruta final contra el directorio base permitido. Tres niveles de ../ bastan para llegar a la raíz del sistema de archivos desde cualquier subdirectorio razonablemente profundo, y de ahí descender hacia etc/passwd.

5.2 Variantes y Técnicas de Evasión de Filtros

Cuando la aplicación intenta filtrar la entrada de forma ingenua (por ejemplo, eliminando ../ una sola vez), existen variantes que evaden esa validación insuficiente:

Variante Ejemplo de payload Filtro que evade
Traversal simple ../../../etc/passwd Ausencia total de validación (caso de este laboratorio).
Codificación URL ..%2f..%2f..%2fetc%2fpasswd Filtros que buscan el carácter "/" literal antes de decodificar la URL.
Doble codificación ..%252f..%252fetc%252fpasswd Servidores/proxies que decodifican una sola vez.
Sustitución no recursiva ....//....//etc/passwd Filtros que eliminan "../" una sola vez (....// → ../ tras el reemplazo).
Ruta absoluta /etc/passwd Filtros que solo bloquean secuencias relativas.

5.3 Impacto y Clasificación Estándar

El pilar principalmente afectado es la confidencialidad (exposición de credenciales, configuración o archivos del sistema); en variantes combinadas con escritura de archivos puede comprometerse también la integridad y, de forma indirecta, la disponibilidad. En este laboratorio el impacto demostrado es lectura de /etc/passwd, clasificada como CWE-22 (Improper Limitation of a Pathname to a Restricted Directory) y encuadrada en OWASP Top 10 2021 — A01:2021 Broken Access Control, ya que en el fondo representa una falla de control de acceso sobre los recursos del sistema de archivos.

Defensa efectiva: combina no confiar en la entrada del usuario, canonicalizar y validar la ruta resultante contra el directorio base permitido, y aplicar el principio de menor privilegio como capa adicional (ver sección 8, Mitigación recomendada).

6. Procedimiento Paso a Paso

Paso 1 — Reconocimiento de la Aplicación

Se accede a la aplicación vulnerable (una tienda en línea) y se navega por la página principal para identificar la funcionalidad de carga de imágenes de producto, la cual constituye el vector de ataque.

Paso 2 — Interceptación del Tráfico con Burp Suite

Con el proxy de Burp Suite activo y el navegador configurado para enviar el tráfico a través de él, se navega por el sitio y se revisa el historial de peticiones (Proxy > HTTP history). Se identifica que las imágenes de los productos se solicitan mediante el endpoint GET /image?filename=NOMBRE, lo cual confirma el parámetro controlable por el usuario.

Paso 3 — Identificación de la Solicitud Original

Se selecciona una de las solicitudes de imagen y se envía al módulo Repeater para su análisis y manipulación controlada.

Paso 4 — Análisis de la Solicitud Completa

Se revisan los encabezados completos de la solicitud (Host, Cookie de sesión, User-Agent, Referer, etc.) para comprender el contexto de la petición antes de modificarla.

Paso 5 — Construcción y Envío del Payload

En el valor del parámetro filename se sustituye el nombre de archivo original por la secuencia de traversal ../../../etc/passwd, con el propósito de retroceder desde el directorio de imágenes hasta la raíz del sistema de archivos y luego descender hacia el archivo de credenciales del sistema.

Paso 6 — Confirmación de la Respuesta Vulnerable

Al enviar la solicitud modificada, el servidor responde con estado 200 OK y devuelve en el cuerpo de la respuesta el contenido íntegro del archivo /etc/passwd, confirmando que la aplicación no valida ni restringe la ruta solicitada.

Paso 7 — Confirmación de Resolución del Laboratorio

PortSwigger Web Security Academy confirma automáticamente la explotación exitosa marcando el laboratorio como Solved.

7. Explicación del Payload

Payload utilizado:

../../../etc/passwd

Funcionamiento técnico:

  • La aplicación construye internamente una ruta similar a /var/www/images/ + filename para localizar y servir el archivo solicitado.
  • Cada secuencia ../ le indica al sistema de archivos que suba un nivel de directorio respecto al directorio base de imágenes (por ejemplo, de /var/www/images/ a /var/www/ y luego a /var/).
  • Se emplean tres secuencias ../ para garantizar que, independientemente de la profundidad exacta del directorio base de imágenes, la ruta resultante llegue a la raíz del sistema de archivos (/).
  • A partir de la raíz, se añade la ruta etc/passwd, que en sistemas Unix/Linux contiene el listado de cuentas de usuario del sistema operativo (nombre de usuario, UID, GID, directorio home y shell asignado).
  • Como el servidor no valida que el nombre de archivo resultante permanezca dentro del directorio de imágenes autorizado (no aplica canonicalización ni comparación contra una whitelist), procesa la ruta manipulada como si fuera legítima y devuelve el contenido del archivo del sistema en la respuesta HTTP.
El hecho de que el archivo /etc/passwd sea legible por el proceso del servidor web (aunque no contenga los hashes de contraseñas, que residen en /etc/shadow) lo convierte en un objetivo estándar para demostrar path traversal, ya que su formato es predecible y fácilmente verificable.

8. Mitigación Recomendada

  • Evitar pasar directamente la entrada del usuario a las APIs del sistema de archivos; en su lugar, usar un identificador indirecto (por ejemplo, un ID numérico o un nombre de archivo interno) que el servidor traduzca a la ruta real mediante un mapeo controlado del lado del servidor.
  • Validar la entrada contra una lista blanca (allow-list) de nombres o extensiones de archivo permitidos, rechazando cualquier valor que no coincida exactamente con el patrón esperado.
  • Canonicalizar la ruta resultante (resolver secuencias ../, enlaces simbólicos y codificaciones) antes de compararla, y verificar que la ruta canonicalizada siga estando dentro del directorio base permitido.
  • Eliminar o rechazar secuencias de traversal (../, ..\, variantes codificadas en URL o Unicode) en lugar de intentar solo removerlas con expresiones regulares simples, que suelen ser evadibles.
  • Aplicar el principio de menor privilegio: ejecutar el proceso del servidor con un usuario restringido que no tenga permisos de lectura sobre archivos sensibles del sistema operativo.
  • Aislar el directorio de archivos servidos mediante mecanismos como chroot jails, contenedores o sistemas de archivos dedicados de solo lectura para el contenido público.
  • Configurar reglas de un WAF (Web Application Firewall) como capa adicional de defensa para detectar patrones de traversal en los parámetros de la solicitud.
  • Registrar y monitorear solicitudes con patrones anómalos en parámetros de archivo (../, %2e%2e, rutas absolutas) para detectar intentos de explotación.
