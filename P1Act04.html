1. Objetivo de la Actividad

Configurar e implementar un escenario de concientización y prueba de ingeniería social en un entorno controlado utilizando Kali Linux y la herramienta Social-Engineer Toolkit (SET). El propósito es comprender el funcionamiento técnico del método de ataque Credential Harvester para analizar los vectores de riesgo y diseñar medidas defensivas eficaces dentro de una infraestructura de red.

2. Descripción del Escenario

La práctica simula un escenario de suplantación de identidad (phishing) en un entorno strictly controlado de laboratorio. Un atacante interno o externo despliega un sitio web señuelo que imita un formulario de inicio de sesión institucional/empresarial para interceptar las credenciales ingresadas por un usuario desprevenido. El entorno se ejecuta sobre una red local privada sin conexión o exposición a servicios o dominios reales de Internet.

3. Configuración del Laboratorio

  • Sistema Operativo Atacante: Kali Linux (VirtualBox)
  • Dirección IP de la Interfaz: 10.0.2.15 (interfaz eth0)
  • Herramientas Utilizadas: Apache Web Server (puerto 80) y Social-Engineer Toolkit (SET) - Módulo Credential Harvester Attack Method
  • Entorno Cliente: Navegador web en máquina de pruebas local conectada al mismo segmento de red

4. Resumen de Funcionamiento y Evidencias

4.1 Identificación de Parámetros y Lanzamiento

Se verificó la IP local mediante ifconfig (10.0.2.15). Se inició la herramienta mediante sudo setoolkit navegando en el menú: Social-Engineering Attacks > Website Attack Vectors > Credential Harvester Attack Method.

4.2 Gestión de Servicios

Ante el conflicto por la ejecución previa de Apache en el puerto 80, se autorizó la detención automática del servicio local para permitir que el módulo harvester tomara el control exclusivo del puerto.

4.3 Intercepción de Credenciales

Al enviar datos en el formulario clonado desde la máquina cliente, la consola procesó la solicitud POST extrayendo exitosamente la información:

POSSIBLE USERNAME FIELD FOUND: Username=Juanito Alcachofa POSSIBLE PASSWORD FIELD FOUND: password=Hola123

5. Flujo de Captura de Información

  1. Petición HTTP GET: El navegador del usuario solicita la IP del servidor atacante, la cual sirve la estructura HTML/CSS clonada.
  2. Envío de Datos vía HTTP POST: El formulario envía los parámetros de texto directamente al servidor en el puerto 80 de Kali Linux.
  3. Procesamiento e Intercepción: El script de SET despliega las variables en consola y las almacena en /root/.set/reports/.
  4. Redirección Disimulada: El servidor responde con una instrucción de redirección HTTP (302) hacia el sitio original para ocultar la captura.

6. Controles de Seguridad Propuestos

  • Autenticación Multi-Factor (MFA / 2FA): Implementar esquemas basados en tokens o llaves FIDO2/WebAuthn.
  • Filtros de Correo y Antiphishing: Configurar registros SPF, DKIM y DMARC en los servidores institucionales.
  • Gestores de Contraseñas Corporativos: Promover el uso de gestores que reconozcan automáticamente el dominio exacto del sitio.
  • Capacitación y Concientización: Ejecutar campañas periódicas de simulación de phishing.

7. Conclusión

La realización de esta práctica permitió comprender la simplicidad técnica con la que un atacante puede estructurar un vector de captura de credenciales mediante herramientas automatizadas como Social-Engineer Toolkit. Se constató la importancia de aplicar controles de autenticación robustos y mantener esquemas continuos de concientización dentro de las organizaciones.
